## FB-01 「ばら」の語と、1が定義されていない位取り盤面

- 状態: 未対応
- 画面: かず → ステージ10「100までの かず」(`num_place`)、ひきざん → ステージ11(`sub_tens` ほか)
- 該当コード: `src/ui/boards.js` の `case 'place-value'`、使用側は `src/gen/g1/number.js:246`、`src/gen/g1/subtraction.js:322,340`

指摘:
1. **「ばら」という日本語が小1に伝わるか疑問。**
2. **ばら側の1つが「1」だと定義されていない。** 10の束は「10の たば」と書いてあるのでまだ読めるが、
   ばらの青い四角が1を表すという根拠が盤面のどこにもない。束と ばらで形も色も別物なので、
   「同じ大きさのものが10個集まって束になっている」という位取りの核心が絵から読み取れない。
3. **やるならブロック形式にすべき。** 1の立方体が10個縦につながって「10の棒」になっている、
   という関係が目で見て分かる描き方(ブロック/棒の関係が同じ単位でつながっている形)にする。

考えられる直し方(着手時に再検討):
- 10の束を「1のブロックが10個連なった棒」として描き、区切り線を入れて10個であることを見せる
- ばら側は同じ1ブロックを同じ大きさ・同じ質感で描く(束と単位が同じだと目で分かるように)
- 語は「10の たば」「1こずつ」など、絵と対応する言い方に見直す(ラベルだけ変えても②は解決しない)

横断確認が必要な箇所: `place-value` を使う3か所すべて。`ten-frame-plus`(20までのかず)や
`teen-remove` も「10のまとまり+ばら」を扱うので、同じ考え方で揃っているか見る。

## FB-02 隣の問題と答えが近すぎる(32のつぎに33)

- 状態: 未対応
- 画面: かず → ステージ10「100までの かず」で発見。原因は共通なので全ライン該当
- 該当コード: `src/gen/index.js` の makePack 選択ガード、`src/engine/spec.js` の validatePack

指摘: 32のつぎに33が出た。狙いではない。「答えがほとんど同じ数ばかり」という傾向を
子どもは敏感に感じ取り、問題を解かずに傾向に流れて答えるようになる。ランダム性を担保したい。

調査結果(実測):
- 全66ステージ×40seed、隣り合う数値の答え 10,330組を測定
  - **差0(まったく同じ): 6.9%**
  - **差1: 32.0%**
  - あわせて **約39%が「隣とほぼ同じ答え」**
- 原因: 既存の分散ルールは「同じ答えの回数」「答えの種類数」しか見ておらず、
  **隣り合う答えの距離を見ていない**。32と33は別の値なので全ての検査を通過してしまう
- 補足: 選択肢も位の入れ替え(23/32/33/43)で作るため、隣の問題と選択肢の見た目まで似る。
  盤面(3たば+2ばら → 3たば+3ばら)も似るので、画面全体がほぼ同じに見える

考えられる直し方(着手時に再検討):
- 隣り合う答えに最小距離を設ける。ただし絶対値ではなく **答えの取りうる範囲に対する相対距離**にする
  (「5までのかず」は答えが1〜5しかないので差1は避けられない。範囲が広い100までのかずでは差1を禁じる)
- あわせて「盤面の見た目が隣と似すぎる」も見る(位取りなら たば の数が2問続けて同じ、など)
- 検査は spec.js に足して、生成側(gen/index.js)のガードと必ず対にする

横断確認が必要な箇所: 数値を答える全ステージ。特に答えの範囲が広い
`num_place` `num_teens` `sub_tens` `add_maketen` など。
